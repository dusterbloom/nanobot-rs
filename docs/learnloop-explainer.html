What happens when you chat with nanobot?

Every conversation triggers a learning pipeline that runs silently in the background. Here's the full journey from your message to a smarter model.

1

You chat normally instant

You send a message. nanobot's agent loop runs — calling the LLM, using tools (file reads, shell commands, web searches), and producing a response. Nothing new here. The magic happens after the response is delivered.

2

Turn signals are captured sync

Before the response reaches you, nanobot snapshots everything about the turn into a TurnOutcome: your prompt, the response, which tools were called (and whether they succeeded), iteration count, reasoning traces (before <think> blocks are stripped), and the full multi-turn message array including tool call arguments and results.

// Captured BEFORE sanitization strips reasoning let reasoning_trace = if content.contains("<think>") { Some(content.clone()) // raw thinking preserved for training };
3

Quality & Surprise scored async

Two heuristic scores are computed instantly (no model inference needed):

Quality Score (0.0 – 1.0)
Base credit (all turns) +0.20
All tool calls succeeded +0.30
Iteration efficiency (1 − used/max) +0.20
Reasoning trace present +0.10
Substantial response (>50 chars) +0.20
Typical good turn ≈ 0.85
Surprise Score (0.0 – 1.0)
40% × Trace complexity longer = more novel
30% × Efficiency ratio short prompt → long trace
30% × Tool diversity unique tool combos
Must exceed threshold default 0.3
4

Perplexity gate decides async

If surprise exceeds the threshold (default 0.3), the turn is recorded to the experience buffer — a local SQLite database at ~/.nanobot/experience.db. Boring, predictable turns are skipped. Once enough surprising experiences accumulate (default: 5), training is triggered.

// Only train on turns worth learning from if surprise <= threshold { return; } // too predictable, skip
// Record with quality + surprise scores eb.record_with_surprise(prompt, trace, response, quality, surprise);
// Enough data? Spawn training if unexported >= 5 && !training_active { spawn_training(); }
5

Rich tokenization background

Training data is tokenized with the full conversation context — not just prompt→response pairs. If tool calls were made, the training sample includes the complete chain:

<|im_start|>user What's the weather in London?<|im_end|> <|im_start|>assistant <tool_call>{"name":"web_search","arguments":{"query":"weather London"}}</tool_call><|im_end|> <|im_start|>tool Partly cloudy, 18°C, humidity 65%...<|im_end|> <|im_start|>assistant London is partly cloudy at 18°C with 65% humidity.<|im_end|>

This teaches the model when and how to use tools — not just what the final answer should be.

6

ANE split-silicon training background thread

A dedicated thread loads the model weights, initializes (or restores) LoRA adapters, compiles ANE kernels for the needed sequence lengths, and runs the training loop. Your inference is never blocked — training runs on CPU/ANE while the LLM keeps responding on GPU.

// Quality weights the gradient — better turns teach more let effective_loss_scale = loss_scale × quality.max(0.1);
// Training loop with early stopping for epoch in 0..3 { for (tokens, targets, quality) in &samples { forward → backward → adam_update() if loss < best_loss { save_checkpoint(); } } } restore_best_checkpoint();
7

Live hot-swap background

When training finishes, the LoRA deltas are saved to disk (~/.nanobot/workspace/lora/) and — if an in-process MLX model is running — hot-swapped into the live model. No restart needed. Your next message already benefits from what nanobot just learned.

How you benefit

You don't need to configure anything. Just use nanobot normally — it handles the rest.

🎯

Better tool usage

nanobot learns when to call tools and how to call them from your real conversations. Over time, it makes fewer unnecessary tool calls and picks the right tool on the first try.

🧠

Adapts to your style

Every successful conversation becomes training data. nanobot learns your preferences — how you phrase things, what tools you use most, and what kind of responses you prefer.

⚡

Invisible & instant

Training runs on a background thread using Apple Neural Engine while inference continues on GPU. You never wait for training — it just happens silently between your messages.

🔒

Fully private

All training happens on your machine. Experience data stays in a local SQLite database. LoRA weights are saved to ~/.nanobot/workspace/lora/. Nothing is uploaded anywhere.

👍

Your feedback matters

Use /feedback good or /feedback bad after any response. Good responses get amplified in training; bad ones get dampened. Your explicit signal directly shapes the model.

♻️

Cumulative learning

LoRA adapters persist across sessions. Each training run warm-starts from the previous checkpoint. Knowledge accumulates — day 30 is smarter than day 1, and day 90 is smarter still.

The feedback loop

Quality signals ensure nanobot learns from the right examples. There are two sources: implicit signals (automatic) and explicit signals (from you).

🤖 Implicit (automatic)

  • ✅ All tool calls returned ok: true
  • ⚡ Used few iterations (efficient)
  • 💭 Had reasoning traces (<think> blocks)
  • 📝 Produced substantial response
  • 🎯 Combined into 0.0–1.0 quality score

👤 Explicit (from you)

/feedback good → quality = 1.0 /feedback bad → quality = 0.0
Aliases: /fb g, /fb b, /fb +, /fb -

Your rating overrides the automatic score and is applied to the most recent experience. High-quality samples get full gradient; low-quality samples are dampened to 10% contribution.

Configuration

LearnLoop works out of the box, but you can tune it in ~/.nanobot/config.json.

{ "perplexityGate": { "enabled": true, // flip the switch "surpriseThreshold": 0.3, // 0.0 = learn everything, 1.0 = very selective "minExperiences": 5, // batch size before triggering training "trainEpochs": 3 // passes over the batch } }

REPL commands:
/train status — see if training is active and how many steps completed
/train enable / /train disable — toggle learning on/off
/train run — manually trigger a training run on pending experiences
/train list — list saved LoRA adapters
/train merge — merge LoRA into base model weights permanently
/feedback good|bad — rate the last response
